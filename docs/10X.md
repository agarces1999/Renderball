## 2b. Lab hygiene lesson (2026-09-04, learned the expensive way)

Concurrency confounds everything at once: Fireworks queueing (a draw that
"failed" with zero tokens after 580s), Prisma pool timeouts, Neon connection
caps, Chromium contention during measure/critic stages. The A/B protocol's
"interleave and hold load constant" rule (docs/HARNESS.md) now has a hard
number: two builds at a time.

## 3. Wave 2 — the fast lane (flagged, A/B vs control)

Levers, each behind a flag, each with a fallback to today's path:

- `RB_EDIT_BLOCKS=on` — SEARCH/REPLACE edit blocks for the **patch site only**
  (6s vs 35-170s; the revision stays full-file by the founder's ab6 verdict).
- `RB_PATCH_SCOPE=section` (2026-09-04, the founder's "no search/replace"
  alternative) — the validator patch re-emits only the PAGES the defects live
  on (`pagesForDetails` locates each defect's page by its literal detail;
  a preamble-only defect falls back to the full-file patch). With this and
  the section revision, the unit of every fix is a page and nothing is ever
  edited line by line. Fast lane v2 pairs (this instead of edit blocks) are
  queued.
- `RB_REVISE_SCOPE=section` — the revision re-emits only the flagged pages as
  complete `SectionN` components, spliced over the originals
  (`lib/harness/splice-sections.ts`; ~3-4k tokens instead of ~17k). A page is
  the unit, not a line — composition-scale freedom kept.
- `RB_AUTHOR_STREAM=on` + `RB_STREAM_CRITICS=on` — critics judge pages as they
  stream out of the author, so the ~40s critic stage hides under authoring
  (sig-verified reuse; never harmful by construction).

Arithmetic for a 5-page deck if all three hold quality: 580s → ~200s
(author 180 + patch 6 + revision ~35 + critics 0 + tail). With a faster
author socket from Wave 1: ~100-120s. Cost falls (fewer re-emitted tokens).

## 3a. The thesis (founder, 2026-09-04: "a more clever, more drastic insight")

Every deck rebuilds the brand from zero and the model never looks at
anything. The 10x logic: **build each brand's deck SYSTEM once, then sample
pages against it.**

1. Once per brand — a design pass writes the design system as code (palette,
   type, chrome, helpers, keyframes, device primitives), informed by a vision
   read of the brand's real homepage (`RB_DESIGN_CARD`; the Anthropic card:
   "pill corners only on CTAs, sharp elsewhere; heavy sans display over a
   refined serif body; color as flat full-bleed bands; no shadows"). The
   system persists and is reused by every later deck, regenerate and animate —
   a company's decks finally match.
2. Every deck — pages written in parallel against the fixed system
   (`RB_AUTHOR_PARALLEL`), N draws per page with the critic keeping the best
   (pages are cheap), then the author LOOKS at the rendered pages and fixes
   what it sees with the mechanical findings named (`RB_REVISE_VISION`,
   `RB_RENDER_TRUTH`), strict-improvement judge unchanged.

Arithmetic: after a brand's first deck, ~60-90s per deck instead of 6-10
min; quality from sampling where variance is largest and from the model
seeing its work; cost ≈ today's. Every piece exists or is verified; the
thesis lane (`heist-thesis-1`, `stripe-thesis-1`: all five flags on, Qwen
socket) runs behind the seeing pair, blind against the control twins.
First parallel-author receipt (heist-parallel-1, Qwen socket): the design
pass took **42s** (6.7k tokens, 7.8KB preamble, 34 plan lines); the five page
passes ran concurrently in **37-64s** each; one page missed its export name
(wrote Section2 for page 2) and was retried (+60s) — now accepted and
renamed instead. Author stage 160s with the retry, ~105s without, vs
141-172s one-call on the same outline. The deck: 66KB, 52 pieces, one chrome
per page, no duplicate piece ids or module constants, critics flagged
**0/5 pages**. Cost $0.63 — the five page passes each thought ~4k tokens;
`RB_PAGE_THINKING` now dials that (default 4000).

`RB_BRAND_SYSTEM=on` is wired (`lib/harness/brand-system.ts`): after a
parallel build's design pass the module preamble is stored per brand (keyed
by site host, fingerprinted on palette/roles/fonts/logo/design card); the
brand's next build skips the design pass for a plan-only call against the
stored system (`pack.ts` `parallel: { pass: "plan" }`), then writes pages in
parallel. A changed brand → fresh design. Storage is a local JSON per brand
for the experiment; the product version wants R2 + Brand-panel editing.

Parallel pair receipts: heist-parallel-1 **373s $0.63** vs heist-control-3
489s $0.48; stripe-parallel-1 **357s $0.58** (2 pages flagged, revision kept
2/2) vs stripe-control-3 469s $0.41. Blind pairs for the founder:
`fastlane-2026-09-04/pairs2.html`. The parallel decks cost more today because the
page passes think ~4k tokens each — the dial to measure next.

`RB_PAGE_DRAWS=N` (1-3) is wired: every page sampled N times concurrently,
each candidate rendered as its scene inside a temp deck and judged by the
critic; the best per page assembles the deck. Open piece: the persistent
per-brand system (storage + Brand-panel editing).

## 3b. Harness levers the founder asked for (2026-09-04, "engineer the harness to pull all the value from the model")

Both flagged OFF; both verification builds queued after the resumed chain.

- `RB_REVISE_VISION=on` — **the reviser sees the page.** Probe-verified the
  same day: qwen3p8-max on our vision wire read a real slide's exact headline
  and page marker back in 8s. With the flag, the section-scoped revision goes
  through `callZaiVision` with the AUTHOR model and the flagged pages'
  screenshots attached ("look at your page"), instead of a blind text
  revision from Kimi's one-sentence weakness. The vision transport gained a
  per-call `model` override; still the one image wire.
- `RB_RENDER_TRUTH=on` — **the machine names the mistakes.** The legacy
  render-truth battery (`findRenderTruthFailures`: overflow, cross/intra-piece
  overlap, rule-through-text, … the 14 canonical kinds) runs on the same
  measurement the critics judged; findings are appended to that page's
  revision note, verbatim ("overflow — 'Money movement…' crosses the right
  edge"). Code reports, the model fixes; never a repair, never a block. The
  harness had NO layout check at all before this (confirmed in build.ts:
  only truth validators, SSR, and the style-per-page gate ran).

## 5. What "10x faster" honestly means

Serial token generation bounds a one-call author at ~90-250s for a 5-page
deck at today's serving speeds. Below ~100s needs either a faster socket
(Wave 1) or parallel page authoring after a design-system pass (the founder's
open question: does cross-page context matter? — testable blind). Perceived
time-to-first-page can drop to ~30-40s with the streaming machinery already
built (pages rendered as they land). Both are on the table after Waves 1-2.
